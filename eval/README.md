# Porto Agent Skill Evaluation

This standalone uv project uses [Smelt](https://github.com/ProjAnvil/Smelt) to evaluate the five Agent SDK skills generated by Porto. It reads the current definitions from `backend/src/porto_chatbot/agent_sdk/skills.py`; it does not keep a second copy of the skill prompts.

## Setup

```bash
cd eval
uv sync
```

uv installs Smelt from its pinned Git commit and Porto from `../backend`. The generated `uv.lock` records the exact dependency revisions.

## Configure models

Edit the ignored `.env` file and set `SMELT_AGENT_MODEL` and `SMELT_AGENT_API_KEY`. Provider-specific `BASE_URL` is optional. Judge defaults to the agent profile, and doctor defaults to judge; fill `SMELT_JUDGE_*` and `SMELT_DOCTOR_*` to use separate models. Challenge runs by default and uses the judge profile unless `SMELT_CHALLENGER_*` is set. Provider can be `openai` (including OpenAI-compatible `BASE_URL`) or `anthropic`.

The `.env` file is ignored by Git. Do not put credentials into the template, tests, or reports.

## Validate and evaluate

```bash
uv run python -m porto_skill_eval preflight
uv run python -m porto_skill_eval full
uv run python -m porto_skill_eval evaluate
uv run python -m porto_skill_eval evaluate --skill prd-analysis
uv run python -m porto_skill_eval doctor --skill prd-analysis
```

Preflight needs no model credentials. It checks skill export, case inventory, fixture-only tools, and Smelt lint. Low lint grades are reported as skill findings and do not fail preflight. `full` runs behavior cases three times, writing review, static lint, two rounds of adversarial challenge, and Smelt doctor mutation tests plus its judge canary. It exits nonzero when an overall score is below 80/100, a challenge score is below 0.8, a doctor mutation score is below 0.2, a doctor case has a red baseline, or the doctor canary is uncalibrated. Use `--min-score`, `--min-challenge-score`, or `--min-doctor-score` to adjust these gates. The standalone `doctor` command defaults to a strict 0.8 mutation threshold and accepts `--min-score` to change it. Reports are saved as Markdown and JSON under `reports/` in a timestamped run directory.

For custom endpoints, set each role's `*_PROVIDER`, `*_MODEL`, `*_BASE_URL`, and `*_API_KEY` values. Agent, judge, doctor, and challenger can use different providers and models.

The suite uses in-memory fixture tools only. It does not call a Porto service, access production data, or expose write-capable tools to the evaluated agent.
