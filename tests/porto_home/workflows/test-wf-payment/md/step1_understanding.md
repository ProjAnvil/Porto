## 目标用户

1. **C端消费者**：通过扫码、H5、APP 内 SDK 发起支付
2. **B端商户**：接入收单 API，管理交易、退款、对账
3. **运营人员**：配置风控规则、管理渠道、处理差错
4. **财务人员**：核对清算数据、下载对账文件

## 核心业务流程

### 支付交易主流程

1. 商户调用统一下单 API，传入订单信息
2. 平台渠道路由模块选择最优支付通道（成功率、费率、限额）
3. 风控引擎对交易进行实时评估（规则 + ML 模型）
4. 通过风控后，调用支付渠道完成扣款
5. 渠道返回支付结果，平台更新订单状态
6. 异步通知商户支付结果（Webhook / MQ）
7. 消费者端跳转支付结果页

### 退款流程

1. 商户发起退款请求（全额/部分）
2. 平台校验退款条件（原订单状态、退款金额、退款时效）
3. 调用原渠道发起退款
4. 退款成功后更新订单状态，通知商户

### 清结算流程

1. T日交易截止后，系统自动归集当日交易数据
2. 按商户维度汇总：应付 = 交易金额 - 手续费 - 分账金额
3. 生成清算文件并与各渠道对账
4. T+1 日发起结算打款至商户银行账户
5. 生成对账报表供商户下载

## 子系统线索（供 Step 2 参考）

基于功能归属和领域边界，初步识别以下子系统候选：

1. **支付核心（payment-core）**：统一收单、渠道路由、订单管理、退款
2. **风控引擎（risk-engine）**：实时风控评估、规则管理、黑白名单
3. **清结算服务（settlement-service）**：交易对账、清算、结算打款、分账
4. **商户门户（merchant-portal）**：商户入驻、密钥管理、交易查询、报表
5. **通知服务（notification-service）**：支付/退款结果异步通知、重试机制
